# Filtering & Operators

Row filters are expressed as query parameters in the form `?column=operator.value`.
MimREST translates them directly into SQL `WHERE` clauses before executing
the query against PostgreSQL. The syntax is PostgREST-compatible, so existing
knowledge and client libraries work out of the box.

<Note>
Values that contain special URL characters (spaces, parentheses, commas, `%`)
must be percent-encoded. For example, a space becomes `%20` and a comma becomes
`%2C` inside a value. Most HTTP clients handle this automatically when you pass
query parameters as a structured object rather than a raw string.
</Note>

Filtering on a column that does not exist, or using an operator that is not in
the tables below, returns `400` with code `PGRST101`. Every filter value is sent
to PostgreSQL as a bound parameter and cast by the database, so a value the
column type cannot hold fails with the PostgreSQL error (for example `22P02`).

## Basic operators

| Operator | SQL equivalent | Example |
|----------|---------------|---------|
| `eq` | `=` | `?status=eq.active` |
| `neq` | `!=` | `?status=neq.deleted` |
| `gt` | `>` | `?price=gt.100` |
| `gte` | `>=` | `?price=gte.100` |
| `lt` | `<` | `?price=lt.50` |
| `lte` | `<=` | `?price=lte.50` |
| `like` | `LIKE` | `?name=like.Al*` |
| `ilike` | `ILIKE` | `?name=ilike.*john*` |
| `match` | `~` (regex) | `?name=match.^Al` |
| `imatch` | `~*` (case-insensitive regex) | `?name=imatch.^al` |
| `is` | `IS` | `?deleted_at=is.null` |
| `isdistinct` | `IS DISTINCT FROM` | `?status=isdistinct.active` |
| `in` | `IN (...)` | `?id=in.(1,2,3)` |
| `not` | `NOT` (negation prefix) | `?status=not.eq.archived` |

<CodeGroup>
```bash Equality filter
curl "http://localhost:9000/v1/rest/a1b2c3d4e5f67890/todos?done=eq.false" \
  -H "ApiKey: <anon_key>"
```

```bash Greater-than filter
curl "http://localhost:9000/v1/rest/a1b2c3d4e5f67890/orders?total=gte.100" \
  -H "ApiKey: <anon_key>"
```

```bash Negation
curl "http://localhost:9000/v1/rest/a1b2c3d4e5f67890/users?role=not.eq.guest" \
  -H "ApiKey: <anon_key>"
```
</CodeGroup>

<Note>
`eq.null` compares against the literal text `null`, exactly as PostgREST does.
Use `is.null` to test for SQL `NULL`.
</Note>

## Pattern matching

The `like` and `ilike` operators support SQL wildcard patterns. Use `*` in place
of `%` - MimREST maps it automatically. A percent-encoded `%` (`%25`) is passed
through and also acts as a wildcard.

| Pattern | Matches |
|---------|---------|
| `like.Al*` | Values starting with `Al` (case-sensitive) |
| `ilike.*john*` | Values containing `john` anywhere (case-insensitive) |
| `match.^[A-Z]` | Values matching a POSIX regular expression |

<CodeGroup>
```bash Prefix match
curl "http://localhost:9000/v1/rest/a1b2c3d4e5f67890/users?name=like.Al*" \
  -H "ApiKey: <anon_key>"
```

```bash Substring match (case-insensitive)
curl "http://localhost:9000/v1/rest/a1b2c3d4e5f67890/products?description=ilike.*coffee*" \
  -H "ApiKey: <anon_key>"
```
</CodeGroup>

## List filtering

The `in` operator matches rows where the column value is one of the items in a
parenthesised, comma-separated list. An item that contains a comma can be
wrapped in double quotes: `?name=in.("Smith, Jane",Doe)`.

<CodeGroup>
```bash Filter by a list of IDs
curl "http://localhost:9000/v1/rest/a1b2c3d4e5f67890/todos?id=in.(1,2,5)" \
  -H "ApiKey: <anon_key>"
```

```bash Filter by a list of string values
curl "http://localhost:9000/v1/rest/a1b2c3d4e5f67890/users?role=in.(admin,editor)" \
  -H "ApiKey: <anon_key>"
```
</CodeGroup>

## Quantified operators

`eq`, `gt`, `gte`, `lt`, `lte`, `like`, `ilike`, `match` and `imatch` accept a
quantifier that tests a column against every item of a list: `op(any)`
matches when the comparison holds for at least one item and `op(all)` when
it holds for every item. The list is written in braces, like an array
literal.

<CodeGroup>
```bash Any of several patterns (like(any))
# Tasks that start with "Read" or end with "docs"
curl "http://localhost:9000/v1/rest/a1b2c3d4e5f67890/todos?task=like(any).%7BRead%25,%25docs%7D" \
  -H "ApiKey: <anon_key>"
```

```bash Above every threshold (gt(all))
curl "http://localhost:9000/v1/rest/a1b2c3d4e5f67890/products?price=gt(all).%7B10,20,30%7D" \
  -H "ApiKey: <anon_key>"
```
</CodeGroup>

A quantifier on any other operator is rejected with `400` (`PGRST101`).

## Null checks

Use the `is` operator with `null` or `not.null` to filter on `NULL` values.
`is` accepts exactly four values: `null`, `true`, `false` and `unknown`; any
other value is rejected with `400`. Other operators (`eq`, `neq`) do not
perform `IS NULL` / `IS NOT NULL` checks.

<CodeGroup>
```bash Rows where deleted_at IS NULL
curl "http://localhost:9000/v1/rest/a1b2c3d4e5f67890/items?deleted_at=is.null" \
  -H "ApiKey: <anon_key>"
```

```bash Rows where deleted_at IS NOT NULL
curl "http://localhost:9000/v1/rest/a1b2c3d4e5f67890/items?deleted_at=not.is.null" \
  -H "ApiKey: <anon_key>"
```
</CodeGroup>

## Array and JSON operators

For PostgreSQL array columns and JSONB columns, MimDB's REST API exposes
additional operators:

| Operator | SQL equivalent | Use case |
|----------|---------------|----------|
| `cs` | `@>` (contains) | Array/JSONB contains all given elements |
| `cd` | `<@` (contained by) | Array/JSONB is a subset of the given value |
| `ov` | `&&` (overlap) | Array shares at least one element with the given value |

<CodeGroup>
```bash Array contains (cs)
# Find rows where the tags array contains both "go" and "api"
curl "http://localhost:9000/v1/rest/a1b2c3d4e5f67890/posts?tags=cs.%7Bgo%2Capi%7D" \
  -H "ApiKey: <anon_key>"
```

```bash JSONB path filter
# Rows whose payload->>'type' is "click"
curl "http://localhost:9000/v1/rest/a1b2c3d4e5f67890/events?payload-%3E%3Etype=eq.click" \
  -H "ApiKey: <anon_key>"
```
</CodeGroup>

To filter on a value inside a `json` or `jsonb` column, put the path in the
parameter name: `payload->>type=eq.click` (URL-encoded as
`payload-%3E%3Etype=eq.click`). Steps may be `->` (JSON) or `->>` (text) and
each key must be a plain identifier or an array index, for example
`data->address->>city` or `items->0->>sku`. Quotes are not accepted inside the
path. The same paths work in `select` and `order`; see
[Read rows](/rest-api/crud#read-rows).

## Range operators

For PostgreSQL range columns (`int4range`, `tstzrange`, and so on):

| Operator | SQL equivalent | Meaning |
|----------|---------------|---------|
| `sl` | `<<` | Strictly left of the given range |
| `sr` | `>>` | Strictly right of the given range |
| `nxl` | `&>` | Does not extend to the left of the given range |
| `nxr` | `&<` | Does not extend to the right of the given range |
| `adj` | `-\|-` | Adjacent to the given range |

The `cs`, `cd` and `ov` operators above also work on range columns.

## Combining filters

**AND (multiple query parameters)** - Multiple filter parameters are combined
with `AND`. The request below returns rows where `done` is `false` AND `id` is
greater than `5`:

<CodeGroup>
```bash AND filter
curl "http://localhost:9000/v1/rest/a1b2c3d4e5f67890/todos?done=eq.false&id=gt.5" \
  -H "ApiKey: <anon_key>"
```
</CodeGroup>

**OR filter** - Use the `or` query parameter with a comma-separated list of
conditions inside parentheses. `and` works the same way, and both can be
negated as `not.or` and `not.and`:

<CodeGroup>
```bash OR filter
# Rows where task starts with "Deploy" OR done is true
curl "http://localhost:9000/v1/rest/a1b2c3d4e5f67890/todos?or=(task.like.Deploy*,done.eq.true)" \
  -H "ApiKey: <anon_key>"
```

```bash Nested AND inside OR
# Rows where (priority=high AND done=false) OR (priority=critical)
curl "http://localhost:9000/v1/rest/a1b2c3d4e5f67890/tasks?or=(and(priority.eq.high,done.eq.false),priority.eq.critical)" \
  -H "ApiKey: <anon_key>"
```
</CodeGroup>

## Full-text search

MimDB's REST API exposes PostgreSQL's full-text search via the `fts`, `plfts`,
`phfts`, and `wfts` operators. These operators require the column to be a
`tsvector` type or use an implicit cast.

| Operator | PostgreSQL function | Description |
|----------|-------------------|-------------|
| `fts` | `to_tsquery` | Standard full-text search; terms must be joined with tsquery operators (`&`, `\|`, `!`). Bare multi-word input is a tsquery syntax error - use `plfts` for free text |
| `plfts` | `plainto_tsquery` | Plain language query (no operators) |
| `phfts` | `phraseto_tsquery` | Phrase search |
| `wfts` | `websearch_to_tsquery` | Web-style query (AND/OR/quotes) |

<CodeGroup>
```bash Full-text search (standard)
# Requires a tsvector column or functional index; "&" is URL-encoded as %26
curl "http://localhost:9000/v1/rest/a1b2c3d4e5f67890/articles?body=fts.database%26indexing" \
  -H "ApiKey: <anon_key>"
```

```bash Plain language search
# Words are ANDed together without operator syntax
curl "http://localhost:9000/v1/rest/a1b2c3d4e5f67890/articles?body=plfts.database%20indexing" \
  -H "ApiKey: <anon_key>"
```

```bash Web-style search
curl "http://localhost:9000/v1/rest/a1b2c3d4e5f67890/articles?body=wfts.database%20-deprecated" \
  -H "ApiKey: <anon_key>"
```

```bash With language config
curl "http://localhost:9000/v1/rest/a1b2c3d4e5f67890/articles?body=fts(english).performance" \
  -H "ApiKey: <anon_key>"
```
</CodeGroup>

Full-text search performance requires a GIN index on the `tsvector` column.
Create one with:

```sql
CREATE INDEX ON articles USING GIN (to_tsvector('english', body));
```
