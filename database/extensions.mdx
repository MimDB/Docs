# Extensions

MimDB supports a curated set of PostgreSQL extensions. Some are
**config-gated** - they require an `[extensions]` entry in `config.toml` and
expose dedicated API surfaces. Others are **project extensions** that are either
installed in every project database at provisioning time or can be switched on
per project through the extensions endpoints.

## Config-gated extensions

These extensions are switched on in `config.toml`. With `enabled = false` (the
default) nothing is loaded, and the matching API routes answer every request
with a 503 "not enabled" error (`VEC-0001` for `/v1/vectors/`, `STAT-0001` for
`/v1/stats/`, `CRON-0001` for `/v1/cron/`). `pg_jsonschema` has no routes of its
own; its flag only marks the extension as API-enabled in the project extension
list.

```toml
[extensions.pgvector]
enabled = true
default_dimensions = 1536
default_distance_metric = "cosine"  # cosine | l2 | inner_product

[extensions.pg_jsonschema]
enabled = true

[extensions.pg_stat_statements]
enabled = true
default_limit = 25
max_limit = 100

[extensions.pg_cron]
enabled = true
max_jobs_per_project = 50
min_interval_seconds = 60
max_command_length = 4096
job_timeout_seconds = 60
lock_timeout_seconds = 10
```

<Note>
`pg_stat_statements` and `pg_cron` also require
`shared_preload_libraries = 'pg_stat_statements'` (or `'pg_cron'`) in
`postgresql.conf`. PostgreSQL must be restarted after changing
`shared_preload_libraries` - a config reload is not sufficient.
</Note>

## Project extensions

Project extensions are installed per project database and can be added or
removed at runtime without restarting the server. Four of them are installed in
every project database when the project is created:

| Extension | Provides |
|-----------|----------|
| `pgcrypto` | Hashing, encryption, `gen_random_bytes()`, `gen_random_uuid()` |
| `uuid-ossp` | `uuid_generate_v4()` and the other UUID generators |
| `pg_trgm` | Trigram indexes and `similarity()` for fuzzy text search |
| `moddatetime` | Trigger function that maintains an updated-at timestamp |

The remaining project extensions are optional and off by default: `pgvector`,
`postgis`, `hstore`, `ltree`, `citext`, `fuzzystrmatch`, `tablefunc`,
`earthdistance`, `cube`, `unaccent`, `intarray`, `isn`, and `pg_jsonschema`.
Switch them on with the toggle endpoint below.

`dblink`, `postgres_fdw`, and `file_fdw` are blocked (`EXT-0002`) because they
allow filesystem access or cross-database connections from inside a shared
PostgreSQL cluster. Cluster-wide extensions managed by the platform (`pg_cron`,
`pg_stat_statements`, `pg_net`) do not appear in the project list.

### List extensions

`GET /v1/platform/projects/{projectID}/extensions`

The extensions endpoints are part of the platform API: authenticate with a
platform user session (dashboard cookie or platform JWT) that holds the `admin`
or `owner` role in the project's organization, or with the deployment's admin
secret. `{projectID}` is the project UUID, not the ref.

```bash
curl http://localhost:9000/v1/platform/projects/<projectID>/extensions \
  -H "Authorization: Bearer <admin_secret>"
```

```json
{
  "data": [
    {
      "name": "citext",
      "display_name": "citext",
      "description": "Case-insensitive character string type",
      "pg_name": "citext",
      "installed": false,
      "available": true,
      "api_enabled": false
    },
    {
      "name": "pgvector",
      "display_name": "pgvector",
      "description": "Vector similarity search - store embeddings and perform nearest-neighbor queries",
      "pg_name": "vector",
      "installed": true,
      "available": true,
      "api_enabled": true,
      "version": "0.8.0"
    }
  ],
  "error": null,
  "meta": { "request_id": "01970000-0000-7000-8000-000000000000" }
}
```

Entries are sorted by `name`. `available` means the extension's files are
present on the PostgreSQL server; `installed` means `CREATE EXTENSION` has run
in this project's database, in which case `version` is present. `api_enabled`
reports whether the matching `[extensions.*]` config section is enabled (only
`pgvector` and `pg_jsonschema` have one; it is `false` for everything else).

### Toggle an extension

`POST /v1/platform/projects/{projectID}/extensions/{name}/toggle`

```bash
curl -X POST http://localhost:9000/v1/platform/projects/<projectID>/extensions/pgvector/toggle \
  -H "Content-Type: application/json" \
  -H "Authorization: Bearer <admin_secret>" \
  -d '{"enable": true}'
```

```json
{
  "data": {
    "status": "enabled",
    "name": "pgvector"
  },
  "error": null,
  "meta": { "request_id": "01970000-0000-7000-8000-000000000001" }
}
```

Enabling runs `CREATE EXTENSION IF NOT EXISTS` in the project database. To
disable, send `{"enable": false}`; this runs `DROP EXTENSION ... CASCADE`, which
also drops any columns, indexes, or functions that depend on the extension. The
`enable` field is required; omitting it returns `EXT-0006` to prevent
accidental disables from empty request bodies.

| Code | HTTP | Meaning |
|------|------|---------|
| `EXT-0001` | 400 | Unknown or unsupported extension name |
| `EXT-0002` | 403 | Extension is blocked in multi-tenant environments |
| `EXT-0003` | 409 | Extension is already installed |
| `EXT-0004` | 409 | Extension is not installed |
| `EXT-0005` | 409 | Extension is not available on this PostgreSQL server |
| `EXT-0006` | 400 | Missing required field `enable` |
| `EXT-0500` | 500 | Toggle failed |
| `EXT-0501` | 500 | Listing failed |

## Extension details

<Accordion title="pgvector - Vector similarity search">
Adds a `vector` data type and HNSW/IVFFlat indexes to PostgreSQL. Use it to
store embedding vectors alongside your data and run fast approximate
nearest-neighbor search.

**Requires:** pgvector installed at the system level on the PostgreSQL server.

**Config-gated:** Yes (`[extensions.pgvector]`). When enabled, MimDB mounts
dedicated endpoints at `/v1/vectors/{ref}/` for managing vector tables and
running similarity queries. The `vector` extension itself is installed per
project with the toggle endpoint (`pgvector`).

**Typical use:** semantic search, recommendation engines, RAG pipelines.

See [Vectors](/vectors/overview) for endpoint reference.
</Accordion>

<Accordion title="pg_cron - Scheduled SQL jobs">
Runs SQL statements on a cron schedule inside PostgreSQL. Jobs are stored in
the `cron.job` table and executed by the `pg_cron` background worker.

**Requires:** `shared_preload_libraries = 'pg_cron'` and
`cron.database_name = '<platform database>'` in `postgresql.conf`, plus a
PostgreSQL restart. Jobs are still executed inside each project's own database.

**Config-gated:** Yes (`[extensions.pg_cron]`). When enabled, MimDB mounts
CRUD endpoints at `/v1/cron/{ref}/jobs` (service role only).

**Limits (configurable):** up to 50 jobs per project, minimum 60-second
interval, 4096-byte maximum command length, 60-second job execution timeout,
10-second lock timeout.

See [Scheduled Jobs](/cron/overview) for scheduling syntax and endpoint reference.
</Accordion>

<Accordion title="pg_stat_statements - Query performance statistics">
Tracks execution statistics (call count, total time, rows, buffer hits) for
every SQL statement executed against the database. Essential for identifying
slow queries.

**Requires:** `shared_preload_libraries = 'pg_stat_statements'` in
`postgresql.conf` and a PostgreSQL restart.

**Config-gated:** Yes (`[extensions.pg_stat_statements]`). When enabled, MimDB
exposes `GET /v1/stats/{ref}/queries` (service role only) returning the top
queries by total execution time.

**Response limits:** 25 rows by default, up to 100.
</Accordion>

<Accordion title="pg_jsonschema - JSON Schema validation">
Provides a `jsonb_matches_schema(schema, data)` function that validates a JSONB
value against a JSON Schema definition. Use it in `CHECK` constraints to enforce
document structure at the database level.

**Requires:** pg_jsonschema installed at the system level on the PostgreSQL
server.

**Config-gated:** The `[extensions.pg_jsonschema]` flag only controls the
`api_enabled` value reported by the list endpoint. The extension itself is
installed per project with the toggle endpoint (`pg_jsonschema`). There are no
dedicated API endpoints - use `jsonb_matches_schema()` directly in your SQL via
the execution endpoint.

**Example:**
```sql
ALTER TABLE profiles
  ADD CONSTRAINT valid_metadata
  CHECK (jsonb_matches_schema('{"type":"object","required":["tier"]}', metadata));
```
</Accordion>

<Accordion title="pgcrypto - Cryptographic functions">
Provides hashing (`digest`, `crypt`), symmetric encryption (`pgp_sym_encrypt`),
and random byte generation (`gen_random_bytes`). Also includes
`gen_random_uuid()` for UUID generation (though PostgreSQL 13+ includes this
natively).

**Requires:** Nothing beyond the standard PostgreSQL installation.

**Config-gated:** No. Installed in every project database at creation.
</Accordion>

<Accordion title="pg_trgm - Fuzzy string search">
Tokenizes strings into trigrams to support fuzzy text matching and similarity
ranking. Enables `GIN` and `GIST` trigram indexes that accelerate `LIKE`,
`ILIKE`, and `%` operator queries, as well as the `similarity()` and
`word_similarity()` functions.

**Requires:** Nothing beyond the standard PostgreSQL installation.

**Config-gated:** No. Installed in every project database at creation.

**Example:**
```sql
CREATE INDEX ON products USING gin (name gin_trgm_ops);
SELECT name FROM products WHERE name % 'wrench' ORDER BY similarity(name, 'wrench') DESC;
```
</Accordion>
