# Buckets

Buckets are containers for objects. Each project can have multiple buckets
with independent visibility settings, file size limits, and allowed content
types.

<Warning>
All bucket management endpoints require the `service_role` key. The `anon`
key and user JWTs are rejected with `403 STOR-0111`. Never expose your
`service_role` key in client-side code.
</Warning>

## Create a bucket

`POST /v1/storage/{ref}/buckets`

Returns `201 Created` with the new bucket.

<CodeGroup>
```bash cURL
curl -X POST http://localhost:9000/v1/storage/a1b2c3d4e5f67890/buckets \
  -H "Content-Type: application/json" \
  -H "ApiKey: <service_role_key>" \
  -d '{
    "name": "avatars",
    "public": true
  }'
```
</CodeGroup>

```json
{
  "data": {
    "id": "01970000-0000-7000-8000-000000000001",
    "project_id": "01970000-0000-7000-8000-000000000000",
    "name": "avatars",
    "public": true,
    "mutations": "owner",
    "created_at": "2025-01-01T00:00:00Z"
  },
  "error": null,
  "meta": {}
}
```

`file_size_limit` and `allowed_types` appear in bucket responses only once they
have been set.

**Request body:**

| Field | Type | Required | Description |
|-------|------|----------|-------------|
| `name` | string | Yes | Bucket name (must be unique per project) |
| `public` | boolean | No | `true` allows anonymous reads. Default: `false` |
| `mutations` | string | No | Who may replace or delete objects: `owner` or `shared`. Default: `owner`. See [Who can change an object](#who-can-change-an-object) |

An empty `name` returns `400 STOR-0001`. A name already used by another bucket
in the project returns `409 STOR-0300`.

## List buckets

`GET /v1/storage/{ref}/buckets`

<CodeGroup>
```bash cURL
curl http://localhost:9000/v1/storage/a1b2c3d4e5f67890/buckets \
  -H "ApiKey: <service_role_key>"
```
</CodeGroup>

```json
{
  "data": [
    {
      "id": "01970000-0000-7000-8000-000000000001",
      "name": "avatars",
      "public": true,
      "created_at": "2025-01-01T00:00:00Z"
    },
    {
      "id": "01970000-0000-7000-8000-000000000002",
      "name": "documents",
      "public": false,
      "file_size_limit": 10485760,
      "allowed_types": ["application/pdf", "application/msword"],
      "created_at": "2025-01-01T00:00:00Z"
    }
  ],
  "error": null,
  "meta": {
    "next_cursor": null,
    "has_more": false
  }
}
```

Results are paginated (default page size: 25, maximum 100; larger values are
capped). Use `?cursor=<id>` with the `next_cursor` from the previous page and
`?limit=<n>` to page through large bucket lists. `?order=desc` reverses the
order. A cursor that is not a UUID returns `400 SYS-0003`.

## Update a bucket

`PATCH /v1/storage/{ref}/buckets/{name}`

Update any combination of `public`, `mutations`, `file_size_limit`, and
`allowed_types`. Only the fields you include are changed.

<CodeGroup>
```bash cURL - make private, add 10 MB size limit
curl -X PATCH http://localhost:9000/v1/storage/a1b2c3d4e5f67890/buckets/avatars \
  -H "Content-Type: application/json" \
  -H "ApiKey: <service_role_key>" \
  -d '{
    "public": false,
    "file_size_limit": 10485760,
    "allowed_types": ["image/jpeg", "image/png", "image/webp"]
  }'
```
</CodeGroup>

Returns `204 No Content` on success, including for a body that changes
nothing; an unknown bucket returns `404 STOR-0201` either way.

**Request body fields (all optional):**

| Field | Type | Description |
|-------|------|-------------|
| `public` | boolean | Toggle public read access |
| `mutations` | string | `owner` or `shared`; who may replace or delete objects |
| `file_size_limit` | integer | Maximum size in bytes for uploads into this bucket. Replaces the server-wide `max_file_size` for simple uploads into the bucket, so it can be lower or higher; resumable uploads are additionally capped by `max_file_size`. `0` removes the bucket limit; `null` leaves it unchanged |
| `allowed_types` | string[] | Allowed content types, matched exactly against the upload's `Content-Type` header value. Empty array removes the restriction; `null` leaves it unchanged |

Sending a JSON `null` for any field is the same as leaving it out: only fields
with a value are changed.

## Delete a bucket

`DELETE /v1/storage/{ref}/buckets/{name}`

<CodeGroup>
```bash cURL
curl -X DELETE http://localhost:9000/v1/storage/a1b2c3d4e5f67890/buckets/avatars \
  -H "ApiKey: <service_role_key>"
```
</CodeGroup>

Returns `204 No Content` on success.

The bucket must be empty (no active objects). If the bucket contains active
objects, the request returns `409 STOR-0303 Bucket is not empty`. Delete all
objects first, then delete the bucket. Objects that are already soft-deleted,
and uploads that never completed, do not block the delete; their remaining
bytes are removed together with the bucket.

## Public vs private

| | Public bucket | Private bucket |
|-|--------------|----------------|
| Anonymous reads | Allowed via `/v1/storage/{ref}/public/{bucket}/{path}` | Not allowed |
| Authenticated reads | Allowed | JWT or API key required |
| Uploads | JWT or API key required | JWT or API key required |
| Information disclosure | All 404 responses are identical (no leaking of bucket/object existence) | All 404 responses are identical |

<Note>
Public buckets serve files at `/v1/storage/{ref}/public/{bucket}/{path}`
with no authentication. All error responses on this path are bare `404 Not
Found` with no error codes, preventing information disclosure about whether
a bucket is public, whether it exists, or whether an object exists.
</Note>

## Who can change an object

Visibility decides who can read. A bucket's `mutations` setting decides who
can replace or delete an object once it exists:

| `mutations` | Replace or delete an object |
|-------------|-----------------------------|
| `owner` (default) | The user who uploaded it, or the `service_role` key. An object uploaded with the `service_role` key has no owner and can be changed only with that key |
| `shared` | Any authenticated user of the project |

Every object records the user who uploaded it. `owner` is the right setting
for an application whose users upload their own files - avatars, attachments,
documents - because a user can never overwrite or remove another user's
upload. `shared` is for a bucket a team edits together, such as the media
library of a site with several editors.

A refused replace or delete returns `403 STOR-0112`. The check runs before the
request body is read, so a refused upload costs no transfer. Uploading a new
object to a free path is allowed in either mode for any authenticated user.

The `service_role` key is the application's own credential and is subject to
neither rule.
